Correction to our previous answer

Our earlier statement that the native allowed_classes flag was absent was wrong. Stock24 and original50 already pass allowed_classes=false on PHP 7. Primary sources

Sources were checked during this review on 28 October 2026 in Brisbane. Version-specific PHP history is distinguished from current PHP defaults. No secondary source substitutes for unavailable Meta documentation.

  1. PHP 7.4 migration: deprecated features. PHP 7.4 deprecates curly string offsets, array_key_exists on objects, magic-quotes accessors and reversed implode arguments.

  2. PHP setcookie. The options-array signature and SameSite support begin in PHP 7.3. Omitting samesite omits that attribute. SameSite=None needs Secure for browser acceptance. Current documentation also lists newer options that do not apply to these older runtimes.

  3. PHP operator precedence. Bitwise AND binds more tightly than bitwise OR; parentheses change which flags are masked.

  4. PHP unserialize. allowed_classes=false prevents restoration of application object classes. The manual still warns against unserializing untrusted input, irrespective of this setting.

  5. PHP hash_equals. Use the known secret string first and user string second. The native primitive is designed for timing-safe equal-length string comparison; a functional test is not a timing benchmark.

  6. PHP random_bytes. random_bytes supplies cryptographically secure bytes from platform entropy sources.

  7. PHP uniqid. uniqid is time-based and is unsuitable when unguessable cryptographic values are required. Hashing its result does not add source entropy.

  8. MySQL 8 regular expressions. Since MySQL 8.0.22 binary-string regex arguments are rejected with ER_CHARACTER_SET_MISMATCH.

  9. libcurl CURLOPT_RESOLVE. Repeated rules for the same host and port replace earlier addresses. A comma-separated multi-address entry is supported from libcurl 7.59.0.

  10. libcurl peer verification. Peer verification validates the certificate trust chain. A failed trust check causes the connection to fail; hostname verification is independent.

  11. libcurl hostname verification. Value 2 verifies that the certificate identifies the requested hostname.

  12. PHP SSL context options. The documented default stream policy enables verification of both certificate trust and peer name. This differs from stock XenForo explicitly disabling cURL peer verification.

  13. PayPal IPN listener flow. IPN validation sends the complete received message back to PayPal using HTTPS POST. Local transport tests do not validate a payment account or live grant logic.

  14. PHP libxml entity-loader controls. libxml 2.9 disables entity substitution by default, but explicit entity/DTD-loading flags change the risk. Runtime version and parser options remain relevant.

  15. Zend Framework 1.12.20 XML scanner. The PHP-FPM heuristic branch is limited to older PHP versions, including versions below 5.6.6. The upstream loadXml call adds LIBXML_NONET unconditionally, so not every change is gated below PHP 5.6.6. This is source comparison, not proof of a bypass in the shipped scanner.

  16. PHP getimagesize caution. PHP cautions that getimagesize alone is not image validation. XenForo also enforces file constraints and scans recognized images for PHP markers; those controls need their own tests.

  17. PHP htmlspecialchars. ENT_COMPAT converts double quotes and leaves single quotes unchanged. PHP 7 defaults must be distinguished from the newer default described on the current manual page.

  18. PHP class-name syntax. Class labels have identifier rules and reserved-word restrictions. Filtering delimiter characters before eval is useful, but does not prove every proxy construction case valid.

  19. jQuery 1.12.4 release. The official release describes a small set of fixes and no expected breaking changes, and recommends Migrate 1.4.1 for the 1.x/2.x series. That is not proof of all third-party add-on compatibility.

  20. jQuery prototype-pollution fix. jQuery 3.4.0 fixes deep-extend behavior that can modify Object.prototype from a source __proto__ property.

  21. jQuery HTML parsing security fix. jQuery 3.5.0 fixes an HTML-prefilter issue; a 1.12.4 version bump does not include that later change. A library-version exposure is not proof of a reachable XenForo exploit.

  22. Microsoft Ajax CDN status. Microsoft says this CDN is no longer actively updated and will be decommissioned in the future. The page does not support the claim that it was decommissioned in 2022. The exact stock jQuery URL also returned HTTP 200 during this verification.

  23. Google Sign-In deprecation and sunset. The page distinguishes the March 31, 2023 deprecation from an unspecified sunset date, and distinguishes the web JS library from other OAuth 2.0 uses. This does not prove a particular legacy forum login works.

  24. Official XenForo 1.5.24 release. The official announcement is dated May 29, 2019, not October 2019. It describes 1.5.24 as the last planned maintenance release.

  25. PHP unsupported branches. PHP 7.3 ended upstream support on December 6, 2021, and 7.4 on November 28, 2022. Application compatibility tests do not verify vendor engine security backports.

  26. jQuery 1.12.0 feature release. The feature release adds APIs including htmlPrefilter and uniqueSort while anticipating no breaking changes. Backward-compatibility expectations differ from an assertion of identical APIs.

  27. ECMAScript encodeURIComponent algorithm. encodeURIComponent encodes reserved characters as component text. The current draft is cited only for this longstanding operation, not for new runtime features.
